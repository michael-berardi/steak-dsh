# Privacy

Steak DSH is a local launcher and plugin bundle for DeepSeek Harness (`dsh`). Its own code ships no analytics SDK, telemetry endpoint or error reporter, and it sends no usage, crash or diagnostic reports. The only network traffic Steak DSH itself starts is the model, update-check and installer traffic listed below; the CLI tools and models you choose follow their own settings.

## Network egress

- **Model requests.** Prompts, file contents and tool results go to the provider for the model you chose: the gateway passed with `--base-url`, your own local server for `local/<id>`, your signed-in Claude Code CLI for `claude-code/<model>`, your signed-in Codex CLI for `openai-codex/<model>`, or your signed-in `agy` for `agy/<id>`. That provider receives what you send it. Keys come from the environment variable named by `--key-env` or from the CLI's own login; Steak DSH never prints them. See [SECURITY.md](SECURITY.md) for the routes and their credentials.
- **Codex token refresh.** An expired Codex file login is renewed with a refresh-token POST to `https://auth.openai.com/oauth/token`, the same request the Codex CLI makes. When the refresh token rotates, the renewed login is written back to the Codex CLI's own `auth.json`. No other route reads or copies a CLI credential.
- **Model listing.** `steak-dsh models` asks those same sources what they offer. The Claude Code route uses the CLI's built-in catalog and keeps the CLI's telemetry switches on; an explicit `claude-code/<model>` id is still sent to the CLI even when it is not listed.
- **Update check.** One anonymous HTTPS GET of `https://api.github.com/repos/<owner>/<repo>/releases/latest`, where owner and repo come from this package's `package.json`. The only headers are the User-Agent `steak-dsh-update-check` and an `accept` header. No version, identifier, usage or machine data is sent. GitHub sees your IP address, as it does for any request.
  - **When:** only from `chat` and `tui` on a terminal, a moment after launch, at most once every 24 hours per machine, with a 4-second timeout and no retries. `run` (headless, including `--json`), piped output, CI and agent hosts (`CI`, `CLAUDECODE`, `CODEX_SANDBOX`, `GEMINI_CLI`) never check.
  - **Off:** `STEAK_DSH_NO_UPDATE_CHECK=1`, or `"updates": { "checkAutomatically": false }` in `$DSH_HOME/steak-dsh.json`.
- **Updating.** Installing happens only when you run `steak-dsh update`, or after you turn on `steak-dsh update --auto on` (off by default). It downloads the release's installer, `SHA256SUMS` and archive from GitHub (or runs npm for an npm copy). Details: [docs/updates.md](docs/updates.md).
- **Installer downloads.** Running an installer downloads the release archive and its SHA-256 checksums from GitHub, and, only when needed, official Node binaries from nodejs.org (checksum-verified) and packages from the npm registry. Both installers set `npm_config_update_notifier=false` for the npm/corepack processes they start. Nothing else in normal use makes a network call from Steak DSH code.

## Telemetry switches

- The launcher forces `DSH_TELEMETRY_MODE=DISABLED` and `DO_NOT_TRACK=1` on every dsh process it starts, including `dsh plugin`; an inherited value cannot turn telemetry back on.
- The Claude Code route keeps `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`, `DISABLE_TELEMETRY`, `DISABLE_ERROR_REPORTING` and `DO_NOT_TRACK` enabled on every CLI process, including `auth status` and model discovery.
- The agy ACP transport passes `--disable-telemetry`; its log file lives in a private per-session folder.
- Both installers set `DO_NOT_TRACK=1` and `DSH_TELEMETRY_MODE=DISABLED` for the npm, corepack and dsh processes they start, and restore the caller's values afterwards.
- Host-app variables (`ULTRATERM_UI_TRANSCRIPT_FILE`, `ULTRATERM_UI_SESSION_ID`, `ULTRATERM_MAIN_SCREEN`) are removed from every child process.

## Local writes

Every file or folder Steak DSH creates has a stated lifetime and either automatic cleanup/retention or a manual deletion step. `$DSH_HOME` defaults to `~/.dsh`; `$XDG_CACHE_HOME` defaults to `~/.cache`.

| Location | Contents | Lifetime and automatic cleanup / retention | How to delete |
|---|---|---|---|
| `$XDG_CACHE_HOME/steak-dsh/update.json` (default `~/.cache/steak-dsh/update.json`) | Time of the last update check, latest version and its first note lines, last error, skipped version, last notice, automatic-install state. Mode 0600, written atomically. | One small file, rewritten in place. | `rm "$XDG_CACHE_HOME/steak-dsh/update.json"` |
| `"updates"` in `$DSH_HOME/steak-dsh.json` | `checkAutomatically`, `auto`, `autoAsked`. | Until you change or delete it. | Delete the `"updates"` key |
| `$DSH_HOME/steak-dsh/logs/update.log` (automatic updates only) | Output of the last automatic install. Mode 0600. | At most 256 KB, rewritten each install; deleted by `steak-dsh update --auto off`. | `steak-dsh update --auto off` |
| A `steak-dsh-update-*` folder in the OS temp folder | The installer and `SHA256SUMS` being checked by `steak-dsh update`. | Deleted when `update` finishes, on success or failure. | Nothing to do |
| `$DSH_HOME/steak-dsh/logs/harness-exit-*.log` (TUI only) | Harness stderr tail (last 64 KiB) plus exit code, time, session id, command and cwd; can include session text. Mode 0600 in a 0700 folder. | Kept until pruned after each new log: only the newest **20** files survive. Older logs are unlinked automatically. | `rm -rf "$DSH_HOME/steak-dsh/logs"` |
| `$XDG_CACHE_HOME/steak-dsh/compile-cache` (or `~/.cache/steak-dsh/compile-cache`) | Node's compiled-code cache for the harness, keyed by code content; no prompts or tokens. 0700 folder, 0600 entries. | Pruned on every launcher start: entries older than **30 days** or beyond **4096 files** (oldest first) are removed, as are empty version folders. `STEAK_DSH_COMPILE_CACHE=0` creates nothing and a caller's own `NODE_COMPILE_CACHE` is never pruned by us. | `rm -rf "$XDG_CACHE_HOME/steak-dsh/compile-cache"`; disable with `STEAK_DSH_COMPILE_CACHE=0` |
| Generated overlay YAML in the OS temp folder (`steak-dsh-*`) | Route, permission, verify and owned-path patch rows for one run or session. One 0600 file in a private 0700 `mkdtemp` folder. | Removed when the run or session exits (also on `exit`/signal), and the previous copy is removed on a live `/model` switch. A crash leaves it for the OS temp cleaner. | `rm -rf /path/to/steak-dsh-<random>` if a crash left one behind |
| Claude Code transport folder in the OS temp folder (`steak-dsh-claude-code-*`) | `tools.json`, `settings.json` and `system.md` for one CLI process. | Removed when that CLI process closes or on any start/error path; a crash leaves it for the OS temp cleaner. | `rm -rf /path/to/steak-dsh-claude-code-<random>` |
| `$DSH_HOME/steak-dsh-acp-*` (agy ACP only) | Minimal bridge agent config and the private `acp-*.log` for one ACP session. | Removed when the session closes; a hard crash can leave one folder, which is not reused. | `rm -rf "$DSH_HOME"/steak-dsh-acp-*` |
| `$CODEX_HOME/auth.json.steak-dsh-<pid>.tmp` (default `~/.codex`) | Temporary copy of a renewed Codex login while it is atomically renamed into place. Mode 0600. | Removed immediately after the rename or on any write error; a hard crash can leave one file per interrupted renewal. Your `auth.json` itself is owned by the Codex CLI. | `rm -f "$CODEX_HOME"/auth.json.steak-dsh-*.tmp` |
| File named by `ULTRATERM_UI_TRANSCRIPT_FILE` (TUI only, host opt-in) | JSONL conversation published to a host terminal: user, assistant, tool-call and tool-result rows; reasoning text is excluded. Each text is capped at 256 KiB and each row at 4 MiB. Mode 0600 in a 0700 folder. | Created only when a host sets both this variable and a UUID `ULTRATERM_UI_SESSION_ID` (and the path ends in `<id>.jsonl`); one session per file, replaced on `/new` or `/resume`. The host owns the file's retention. Those variables are stripped from every child process. | Delete the session file the host created, for example `rm "$ULTRATERM_UI_TRANSCRIPT_FILE"` |
| `$DSH_HOME/steak-dsh.json` (user config/state) | Trusted project paths, verify commands, per-model guidance and the `"updates"` switches above. Steak DSH reads it; only the update switches are ever written, other keys are kept, and a file that is not valid JSON is never overwritten. | One file, retained until you change or remove it. | `rm "$DSH_HOME/steak-dsh.json"` |
| Session history under `$DSH_HOME` | Conversation/session state kept by the installed `dsh`, not by this bundle. | Retained under dsh's own policy; the launcher does not add to it directly. | Use dsh's own session commands, or `rm -rf "$DSH_HOME"` |
| Installer files under `~/.steak-dsh` (`%LOCALAPPDATA%\steak-dsh` on Windows) and shims under `~/.local/bin` | Release copies (`app/release-<version>` with `app/current`), private Node and dsh when needed, and command shims. | Re-running an installer (or `steak-dsh update`) replaces the private Node/dsh and keeps only the release that was current as the one rollback copy; every other old release folder is deleted. The launcher removes the rollback copy after the new release finishes one session, or after 7 days. Installer temp folders are removed by an `EXIT` trap (POSIX) or `finally` block (Windows). | Follow the removal steps under [Install](README.md#install) |

## Uninstall

Run `steak-dsh update --auto off`, then delete the install directory and command shims as described in [Install](README.md#install), and remove the bundle with `dsh plugin --profile headless remove steak-dsh` if you added it. Delete `~/.cache/steak-dsh` (the update cache and the compile cache) and `$DSH_HOME` for local data, or just the `"updates"` key in `$DSH_HOME/steak-dsh.json` to keep your other settings. Login and sign-in data kept by the Claude Code, Codex or agy CLIs belongs to those tools; remove it with their own logout commands.
